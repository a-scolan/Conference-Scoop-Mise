00 Accroche

Les 4 blocages que tout dev Windows a vécus

ERREUR #1 · LE MUR DU VENDREDI

« Voulez-vous autoriser cette application ? »

Un simple outil CLI exige les droits administrateur (UAC). Billet DSI ouvert, ticket en attente 3 jours.

ERREUR #2 · LE FANTÔME DU PATH

« 'node' n'est pas reconnu en tant que commande »

L'outil a été installé via un installeur MSI... mais le PATH n'a pas été rechargé, ou pointe sur un binaire inexistant.

ERREUR #3 · LE CONFLIT DE RUNTIMES

« Required node version "20", current is "18.2" »

Projet A en Node 18, Projet B en Node 22. Le dev passe son temps à jongler avec nvm ou à casser son poste.

ERREUR #4 · LA CLAQUE MULTIPLATEFORME

« This script is only supported on Linux/macOS »

Un README rédigé sur Mac par le lead dev. Sur Windows, les outils manquent, les scripts bash échouent.

01 Scoop · User Space

Scoop : vos outils dans votre profil, sans admin

PRINCIPE #1

Zéro UAC

Scoop décompresse les binaires dans ~/scoop/apps. Aucun installeur MSI ne pollue le registre machine ni n'exige de droit élévé.

PRINCIPE #2

Les Shims

Un seul dossier dans votre PATH : ~/scoop/shims. Chaque outil y dépose un petit proxy (.exe / .cmd) pointant sur la version active.

PRINCIPE #3

Buckets Git

Les catalogues d'applications sont de simples dépôts Git de manifests JSON (main, extras, versions ou votre bucket interne d'entreprise).

02 Mise-en-place

Mise : la version du runtime suit le projet, pas le poste

POLYGLOTTE

Un seul outil

Remplace nvm, pyenv, rbenv, sdkman, goenv... Écrit en Rust, ultra-rapide (5 ms au prompt) et fonctionne nativement sous Windows.

DÉCLARATIF

mise.toml

03 Windows Internals

Le piège du PATH : HKLM passe toujours avant HKCU

LA RÈGLE WINDOWS

Fusion descendante obligatoire

À la création de session (CreateEnvironmentBlock), Windows concatène le PATH Machine (HKLM) avant le PATH Utilisateur (HKCU). Impossible d'inverser ce comportement sans droits administrateur.

LA CONSÉQUENCE CACHÉE

Le masquage (Shadowing)

Si l'image entreprise contient un vieux Python 3.9 dans C:\Python39 déclaré au niveau Machine, votre Python 3.12 installé proprement via Mise ne sera jamais appelé par défaut dans vos scripts !

03 Démo PATH

En direct : débusquer le masquage avec where.exe

Diagnostic · Ordre de résolution Windows HKLM vs HKCU 
# Le piège : l'exécutable système passe en premier
> where.exe python
C:\Python39\python.exe                    <-- HKLM (Machine legacy)
C:\Users\alexis\AppData\Local\mise\shims\python.exe  <-- HKCU (Ignoré !)

# La parade DevRecipe : shims_prepend.cmd via AutoRun cmd.exe
# et injection au début du PATH dans le profil PowerShell ($env:PATH)
> devrecipe -Review
[OK] User shims prepended at index 0 of current PATH

> where.exe python
C:\Users\alexis\AppData\Local\mise\shims\python.exe  <-- Prioritaire !
C:\Python39\python.exe
04 REX · DevRecipe

DevRecipe : l'onboarding d'équipe devient une PR

MANIFESTE TOML

Code Review

Fini le wiki obsolète de 15 pages. La liste des outils requis (Scoop) et des runtimes (Mise) est déclarée en code et validée en équipe.

PREFLIGHT CHECK

Détection des conflits

Avant de toucher au poste, DevRecipe inspecte les désinstalleurs Windows, AppX et le PATH pour alerter si un outil tiers entre en collision.

DRY-RUN & PROFILS

Zéro effet de bord

-DryRun montre exactement les actions qui seront exécutées. Les profils (default, ai-agents, cloud) ciblent les besoins réels.

04 Sécurité · Entreprise

Gouvernance : User Space ≠ Shadow IT

CONTRÔLE

EDR & AppLocker actifs

Installer en User Space ne contourne aucun antivirus d'entreprise, ni WDAC ni les restrictions d'exécution. Tout binaire non autorisé reste bloqué.

PROCURATION

Buckets approuvés

L'entreprise peut héberger son propre bucket Git privé avec des manifests validés par les équipes cybersécurité et des miroirs internes.

TRANSPARENCE

Auditabilité complète

scoop export et mise ls --json permettent de générer un inventaire machine instantané pour la conformité et les revues sécurité.
